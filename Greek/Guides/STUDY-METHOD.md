# Μεθοδολογία Μελέτης

Αυτός ο οδηγός δίνει μία κοινή μέθοδο για όλα τα modules του Hacking Guide Project, ώστε οι ίδιες γενικές οδηγίες να μην επαναλαμβάνονται μέσα σε κάθε μάθημα.

## 1. Καθόρισε πρώτα το όριο

Πριν από οποιαδήποτε πρακτική άσκηση, γράψε τι σου ανήκει ή τι έχεις ρητή εξουσιοδότηση να ελέγξεις, ποιοι λογαριασμοί και δεδομένα είναι synthetic, ποιες ενέργειες απαγορεύονται και πότε πρέπει να σταματήσει η δοκιμή. Αν το scope δεν είναι ξεκάθαρο, κράτησε την άσκηση θεωρητική ή χρησιμοποίησε απομονωμένο local lab.

## 2. Μελέτησε σε τρία περάσματα

### Πέρασμα A — Χτίσε το μοντέλο

Διάβασε το μάθημα χωρίς να προσπαθείς να απομνημονεύσεις commands. Εντόπισε assets, identities, trust boundaries, data flows, security invariants και failure modes. Αν δεν μπορείς να εξηγήσεις την αρχιτεκτονική με απλά λόγια, μην βιαστείς να χρησιμοποιήσεις εργαλεία.

### Πέρασμα B — Βρες το evidence

Για κάθε ισχυρισμό σκέψου ποιο evidence θα τον επιβεβαίωνε ή θα τον διέψευδε: configuration, request/response, packet trace, log event, process state, file metadata, policy decision ή αποτέλεσμα ελεγχόμενου test. Προτίμησε πρωτογενή evidence αντί για screenshots από συνοπτικό tool output.

### Πέρασμα C — Κάνε ασφαλή πρακτική

Χρησιμοποίησε τη μικρότερη ακίνδυνη άσκηση που αποδεικνύει την έννοια. Πάρε baseline, άλλαξε μία μεταβλητή κάθε φορά, κράτησε before/after evidence, επανάφερε το περιβάλλον και γράψε τι έμαθες.

## 3. Κράτα lab record

Για κάθε άσκηση σημείωσε:

- στόχο και security question,
- εξουσιοδοτημένο scope και περιβάλλον,
- αρχική ρύθμιση ή baseline,
- ακριβή benign ενέργεια,
- expected result,
- observed result,
- σχετικά logs, outputs ή artifacts,
- εξήγηση root cause ή control,
- cleanup/recovery,
- μία επόμενη ερώτηση.

Μην αντιγράφεις πραγματικά credentials, άσχετα προσωπικά δεδομένα ή production secrets στις σημειώσεις.

## 4. Χώρισε observation από inference

Χρησιμοποίησε **Παρατήρηση** για γεγονότα που αποδεικνύονται άμεσα από evidence και **Συμπέρασμα** για όσα εξαρτώνται από υποθέσεις. Πρόσθεσε confidence όταν χρειάζεται. Έτσι ένα scanner result ή ένα μεμονωμένο log δεν μετατρέπεται σε υπερβολικά βέβαιο finding.

## 5. Χρησιμοποίησε security invariants

Security invariant είναι κάτι που πρέπει να παραμένει αληθινό, για παράδειγμα:

- normal user βλέπει μόνο objects του δικού του tenant,
- guest network δεν φτάνει το management plane,
- unsigned build δεν μπορεί να γίνει release artifact,
- revoked identity δεν συνεχίζει να χρησιμοποιεί protected service.

Η δοκιμή ενός invariant είναι συνήθως πιο χρήσιμη από μεγάλη λίστα άσχετων commands.

## 6. Evidence hygiene

Προτίμησε synthetic accounts και test objects. Κάνε redaction σε secrets. Χρησιμοποίησε hashes όταν χρειάζεται integrity. Διατήρησε timestamps και time-zone context. Μην πειράζεις νόμιμα audit/security logs. Κράτα lab evidence μόνο όσο απαιτείται.

## 7. Συνηθισμένα γενικά λάθη

- Έναρξη από tool χωρίς κατανόηση του συστήματος.
- Επέκταση scope επειδή εμφανίστηκε κάτι ενδιαφέρον.
- Θεώρηση ότι ένα successful request αποδεικνύει business impact.
- Συλλογή περισσότερων δεδομένων από όσα χρειάζονται.
- Αλλαγή πολλών μεταβλητών ταυτόχρονα.
- Απουσία baseline.
- Παρουσίαση αβεβαιότητας σαν βεβαιότητα.
- Test accounts/files/configuration που μένουν μετά το lab.

## 8. Έλεγχος mastery

Ένα module θεωρείται ολοκληρωμένο όταν μπορείς να:

1. εξηγήσεις το βασικό μοντέλο χωρίς να κοιτάς το κείμενο,
2. εντοπίσεις τα σημαντικά trust boundaries και failure modes,
3. επιλέξεις evidence που ελέγχει έναν security claim,
4. ολοκληρώσεις τουλάχιστον μία ασφαλή άσκηση,
5. εξηγήσεις τόσο την αδυναμία όσο και το defensive control,
6. πεις τι θα έλεγχνες μετά και γιατί.

## 9. Χρησιμοποίησε το menu

Άνοιξε το `Hacking Guide Project.py` και χρησιμοποίησε το αριθμημένο interface. Η **Αναζήτηση μαθημάτων** βρίσκει concepts, η **Περιήγηση κατηγοριών** κρατά σχετικά modules μαζί, οι **Διαδρομές μάθησης** δίνουν σειρά μελέτης, τα **Bookmarks** αποθηκεύουν χρήσιμα lessons και η **Πρόοδος & πρόσφατα** σε επιστρέφει εκεί που σταμάτησες.

## 10. Ρυθμός μελέτης

Σε δύσκολη ύλη είναι καλύτερο ένα module που κατάλαβες σε βάθος παρά πολλά που απλώς διάβασες. Διάβασε, μοντελοποίησε, κάνε ασφαλή πρακτική, γράψε evidence, απάντησε το knowledge check και μετά προχώρησε. Επέστρεψε σε παλιότερα modules όταν ένα επόμενο μάθημα αποκαλύπτει κενό σε prerequisite.
